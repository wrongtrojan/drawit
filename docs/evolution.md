# drawit 演进说明

这份说明记录本轮语义图元、现有图元优化与 MCP 目录的实现边界及验收要求。已经固定的架构、运行和打包见 [maintenance.md](maintenance.md)。给人用的操作见 [guide.md](guide.md)。现有回归提示词见 [scenarios.md](scenarios.md)。

上一轮四条工作流里写下的优先项已经落地：时序图、表格、分层容器、标注箭头、对齐分布吸附、编辑器快捷键和文档列表、MCP 的目录与审查图、随包会话。本说明不重做这些。组件库看起来少，是因为上一轮没有把类图、ER、泳道放进优先清单。

## 不要改动的边界

唯一事实来源仍是 `DiagramDocument`。新图元是注册表里的一种节点，经 `DiagramOperation` 进入同一个控制器，由 `packages/render` 的同一个 SVG 渲染器画出。语义字段留在节点上。不提供整份文档覆盖。不执行 Agent 提交的脚本。审查工具成功只表示图已生成。

新类型的坐标规则与现有节点相同：没有父节点时相对画布，有 `parentId` 时相对父容器。自动布局仍只在显式调用时运行，并跳过 `pinned` 节点。

## 现在能画什么

注册表在 [packages/core/src/registry.ts](../packages/core/src/registry.ts)。基础形状有矩形、圆角矩形、椭圆、菱形、三角形、多边形、文本、注释、容器、图片和目标标注。领域图元有流程图四种、时序图三种、表格、架构分层、数组、栈、队列、树和图。数学图元有公式、矩阵、向量、括号和公式注释。

架构分层是加宽的容器，不是另一种节点。树和图各是一个节点。树按叶子跨度与深度绘制，重名标签依靠结构路径区分；有向无环图按拓扑层次绘制，其他图采用网格。矩阵已能按行、列和单元格高亮。

下面这些场景继续用现有图元，不为它们再做一个换皮矩形：

- 数学里的矩阵乘法和贝叶斯更新，用矩阵高亮和公式。
- 计算机里的二分查找，用流程图。虚拟内存的页表，用表格。
- AI 里的注意力块、训练步和分层架构，用容器、连线和公式。请求往返用时序图。
- 办公里的季度复盘和发布步骤，用容器、表格和流程图。

## 本轮已接入的图元

只加语义无法还原成匿名矩形的类型。以下八种类型已进入 schema、默认几何、注册表、共享渲染器和属性面板。[scenarios.md](scenarios.md) 已追加每种类型的简略与详尽提示，工程在 `examples/evolution/`。

- **类** `class`：类名、属性列表、方法列表。可选构造型。类与类之间仍用现有连线，标签写继承、关联或依赖。
- **ER 实体** `entity`：实体名和属性列表。
- **ER 联系** `relationship`：联系名。与实体之间用现有连线，标签写基数。
- **状态** `state`：`initial`、`state`、`final` 三种，加上显示文字。转移用现有连线；初始和终止状态连接到可见圆形符号的边缘。
- **泳道** `swimlane`：标题和方向（横向或纵向）。泳道内的步骤用 `parentId` 放进去，坐标相对泳道。计算机流程图和办公流程共用这一种。
- **数轴** `axis`：方向、最小值、最大值、刻度和轴标题。用来画区间、坐标系和向量方向。概率树不新加类型，继续用树。
- **张量** `tensor`：名字和形状字符串，例如 `x` 与 `[B, T, d]`。残差相加继续用带文字的圆角矩形或公式，不单列类型。
- **里程碑** `timeline`：一条轴和若干 `{ date, label }`。组织关系不另做图元，继续用树。

## 现有图元的实现规则

保持现有类型，优化以下渲染和尺寸规则。语义字段保持不变，保存后再打开仍然是同一种节点。

- **树**：按叶子数和深度计算节点尺寸，长标签用能放下文字的形状，而不是挤进半径 14 的圆。父子连线按树结构连接。父子边按结构路径连接，重名标签仍然连对。目录里的树示例至少包含两层孩子。
- **图**：边画到顶点边缘，并显示边上的标签。路径和层次明显的图不要一律排成圆。顶点变多时节点跟着变大，避免圆互相重叠。
- **矩阵、向量、数组、栈、队列、表格**：单元格随内容变宽变高，或在格内换行。列宽按内容计算，行高按实际换行计算，合并区域仍保留。矩阵的行、列和单元格高亮保持不变。

概率树、组织关系和页表继续用优化后的树或表格，不另做图元。

## MCP 组件选择说明

改图的回路已经够用，保持不动。服务器说明、`expectedRevision`、`diagram_get` 交回的文档与绝对坐标、`diagram_review_snapshot` 的 PNG 和 id 清单、以及 `align`、`distribute`、`snapToGrid` 都留在现有工具里。

`diagram_catalog` 现在提供适用情形、语义字段短列表、最小节点示例、可直接提交的 `exampleOperations` 和组合顺序。详细 schema 通过 `includeSchema: true` 查询。`diagram_add_nodes` 及事务中的 addNodes 使用按类型定义的输入 schema；不支持的类型明确拒绝，文档不变。

目录的每条组件给出三样东西，数据仍只来自注册表，不在工具描述里再抄一份：

- 适用情形，用一句人话写清，例如矩阵乘法使用 `matrix` 并填写 `highlightRows`、`highlightCols`、`highlightCells`；贝叶斯使用 `equation`。
- 一条可以直接提交的最小示例，包含真正有语义的字段。
- 组合顺序。时序图先放生命线，消息和激活条再引用它们的 id。放进容器或泳道的坐标相对父节点。

目录同时列出当前没有的图种名称。尚未实现的规划类型回答“还没有该类型，不要用匿名矩形冒充”。本轮八种类型均已接入，因此 `unsupported` 当前为空；名单由注册表中的实际类型生成。

几何、样式和默认宽高仍留在 schema 里，但不要让它们盖过适用情形和示例。必填语义字段要出现在目录的短字段列表中，即使 schema 给了默认值。

## 验收

一种新类型算完成，要同时满足：

- Agent 只读到工具描述和 `diagram_catalog`，就能按对应领域的简略提示画出该类型，字段不是拆碎的矩形。
- 同一条详尽提示里的关系和文字都在。人看审查图，没有明显重叠、裁切、指错的箭头或挡住节点的标签。工具成功不算通过。
- 界面可以编辑这些语义字段。保存后再打开，id 和字段不变。
- 过期的 `expectedRevision` 被拒绝，文档不变。

树、图和表格类的优化单独验收：两层以上且含重名标签的树，父子连线正确，文字不被圆裁掉。至少三个顶点、带边标签的图能看出边，箭头不穿进顶点。矩阵或表格里的长文本在审查图中仍然可读。

[scenarios.md](scenarios.md) 里已有的 22 条提示词保持原文。新增图元只追加样本，不改已有条目的通过标准。Linux 安装包验收和公开签名不在这一轮。

## 不做

不做手绘、多页、云端素材、从磁盘加载的插件脚本、账号、云同步和付费识图。不为每个模型或产品做一个图标。未接通的能力不留空按钮；还没有的图种只写在目录的否定清单里。

## 验证与后续边界

内容尺寸由 `packages/core/src/contentLayout.ts` 计算，作为画布、导出、校验、视图和显式布局的共同依据。存储的宽高是最小外框；绘制尺寸可随内容增大，位置不自动改变。`diagram_get` 的 view 提供 renderedWidth/renderedHeight，工程里的 id 与语义字段保持不变。泳道标题带为横向左侧 48、纵向顶部 42；显式布局为步骤保留标题空间，不修改 pinned 泳道的几何。

生成工程与审查图：`pnpm examples:evolution`。自动化检查见 [maintenance.md](maintenance.md)。本轮不改安装包和协议。Agent 的单提示盲测及人的视觉验收仍与自动化测试分别进行，不把渲染成功记为图已合格。

后续可优化循环图的双向边路由、按真实时间比例绘制的时间线，以及已有矩阵高亮的更多界面控件；不新增没有语义的换皮矩形。
